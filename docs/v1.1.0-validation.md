## Сохранность игровых данных

Механические ключи, значения `option`, идентификаторы документов, формулы, цены и расчёты не переводятся. Произвольные пользовательские тексты не считаются штатными только по наличию знакомого английского слова.

Три подсказки полей редактора предметов получили русское объяснение и канонический пример ввода. В этих полях парсер системы требует английские имена свойств, идентификаторы групп и формулу дальности. Например, `Tearing` и `20 metres x psy rating` оставлены как синтаксис данных. Проверено, что замена этих выражений русскими словами ломает их распознавание.

Названия оружия транспорта показываются по-русски в представлениях. Хранимое английское имя и `gearKey` сохраняются, поскольку исходная система использует их при подборе боеприпасов. При явном применении штатного профиля переводятся его точные исходные описания и имя машины, если пользователь выбрал переименование.

Поля настроек с редактируемыми штатными названиями используют видимое поле перевода и исходное поле для отправки. Без ручной правки отправляется исходное значение. Настоящая правка сохраняется. Проверены повторный рендер, `required`, `readOnly`, доступное имя, FormData и сброс формы.

Новые штатные эффекты получают русский текст при создании. Для существующих эффектов перевод редактора обратим: сохранение без правок возвращает исходное имя и описание, а ручная правка остаётся правкой пользователя.

## Автоматические проверки

Все 24 набора `tools/test-*.mjs` проходят в Node.js 24. Дополнительно выполнены проверка синтаксиса модулей, `git diff --check` и интеграционные проверки DOM с jsdom. Проверены взаимодействие нового и прежнего адаптеров, смена языка, повторная отрисовка и сохранность параметров уведомлений.

Команды из каталога модуля:

```bash
for test in tools/test-*.mjs; do node "$test" || exit 1; done
node tools/verify-ru-locale.mjs /path/to/system/lang/en.json
node tools/audit-current-source.mjs /path/to/system
```

Для проверки полноты снимка к последней команде можно добавить `--manifest /path/to/source_manifest.json`. Манифест содержит `system.files` с путями из дерева GitHub. Без манифеста инструмент честно оставляет полноту снимка неопределённой.

Расширенная проверка форм и хуков использует jsdom, установленный отдельно от модуля:

```bash
DH2E_RU_JSDOM=/path/to/node_modules/jsdom/lib/api.js node tools/test-stock-ui-v110.mjs
```

## Проверка в Foundry

Живой мир Foundry VTT 14 в этой среде недоступен. Следующие сценарии требуют проверки в установленной игре и не отмечены как пройденные:

1. Создать аколита, выбрать происхождение и стартовое снаряжение, проверить существующего персонажа и Бестиарий.
2. Купить развитие, выполнить атаку и психическую проверку, открыть результаты, поддержание и эффекты Варпа в чате.
3. Добавить состояние, открыть его подсказку и редактор, сохранить без правок и с ручной правкой.
4. Применить каждый профиль транспорта, открыть оружие и HUD, израсходовать и перезарядить магазин, выполнить ремонт.
5. Открыть настройки системы и укрытия, сохранить без правок, изменить подпись и повторно открыть окно.
6. Повторить ключевые операции с правами игрока и Мастера, после перезагрузки клиента и при установленном префиксе адреса сервера.

Диагностика известных английских надписей в открытых окнах:

```js
game.modules.get('dark-heresy-2e-apex-ru')?.api?.inspectOpenSystemUI?.()
game.modules.get('dark-heresy-2e-apex-ru')?.api?.viewBridgeStatus?.()
```

Диагностика не заменяет игровой прогон. Установка версии 1.1.0 не означает, что 100% всех состояний интерфейса уже проверены в Foundry.
